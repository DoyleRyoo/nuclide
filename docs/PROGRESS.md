# 구현 진행 현황

기준일: 2026-09-27. 다음 작업자가 바로 이어서 구현할 수 있도록 현재 상태, 검증 결과, 남은 일을 정리한다. 설계는 [설계 문서 목록](README.md), 결정 기록은 [06 §4](06-roadmap.md#4-결정-기록-adr)에 있다.

## 1. 요약

- **P0 기능은 모두, P1 기능은 대부분 구현했다.** 로컬에서 타입 검사, 린트, 단위 테스트 66개, 데이터 검증, 빌드, 번들 예산, E2E 31개가 통과한다(§2).
- **구현 전체가 아직 커밋되지 않았다.** 저장소에는 설계 문서만 담은 커밋(`922bb0a first commit`) 하나뿐이고, 코드·데이터·설정은 모두 추적되지 않은 파일이다(`develop` 브랜치). push와 공개 배포도 하지 않았다.
- 공개(v0.1) 전에 남은 큰 일은 프레임 성능 측정, 오프라인·배포 경로 확인, Lighthouse, 실기기·스크린리더 확인, 데이터 이용 조건 검토다(§8).

## 6. 설계에서 바뀐 점 (설계 문서에 반영 완료)

- **데이터를 두 청크로 나눴다 ([ADR-14](06-roadmap.md#4-결정-기록-adr)).** 한 파일로는 gzip 603 KB라 시작 데이터 예산 250 KB를 넘었다. 반올림 전 AME 값이 거의 압축되지 않기 때문이다(처음 예상 150–200 KB는 틀렸다). `nuclides.json`(NUBASE + 핵자당 결합에너지)은 시작할 때, `ame.json`(나머지 AME 값)은 첫 차트 뒤 `loadAmeDetails()`로 받고 `store.ameReady`를 켠다.
- **파일에는 원본 값만 저장한다.** ID·범주·딸핵·초 단위 반감기·주 모드 등은 `hydrate()`가 채우고, 빌드 검증도 hydrate 결과에 대해 돈다(04 §7).
- **JSON은 `?raw` 문자열 + `JSON.parse`로 불러온다.** 그냥 import하면 Vite 8이 1 MB가 넘는 JS 객체 리터럴로 내보내 Chrome 모듈 평가에만 약 105 ms가 걸렸다(05 §6).
- **원본에서 새로 찾은 형식**(04 §4.4, §5.1, §5.2, §13): 부호 없는 `B` 토큰(¹²⁶Pdᵐ³에만 있고 β−로 해석, 다른 곳에 나오면 빌드 실패), `B-=?` 형식, `non-exist` 들뜬 상태 16개, `stbl`·빈칸 반감기의 한계값(불확도 칸). 스키마에 `DecayBranch.est`, `NuclearState.nonExistent`, 저장 형식 타입(`Stored*`, `AmeDetailFile`)을 추가했다.
- **배치**(02 §1.1): 범례는 왼쪽 위, 미니맵은 오른쪽 아래로 옮겼다. 차트 띠가 대각선이라 두 모서리가 비어 있고, 처음 배치(둘 다 왼쪽 아래)는 전체 보기에서 가벼운 핵종을 가렸다. 앱 이름에 카드 배경을 주고, 축 설명을 지도 정보 알약 안으로 옮겼다.
- 패널·시트가 열려 가용 영역이 줄면 선택 칸이 보이게 이동한다(02 §6.1). 모바일 딥링크에서 선택 칸이 시트 뒤에 숨던 문제를 고쳤다.
- 붕괴 화살표는 0.01 % 미만 분기를 생략하고 LOD ≥ 1에서 칸 가장자리에서 출발한다(03 §6.3). 마법수 선은 s < 6에서 가늘게, 라벨이 겹치면 작은 쪽을 생략한다(03 §6.1). 색 지도는 다항식 근사로 계산한다(03 §4).
- 엔진 이벤트 `navigate`(방향키 이웃 선택), `activate`(Enter·Space)를 추가했다(05 §4.1).

### 이번 정리에서 고친 문서 불일치 (2026-09-27)

- ADR 번호 중복: "데이터 두 청크" 결정이 기존 ADR-13(AME 반올림 표시)과 같은 번호였다. ADR-14로 바꾸고 01·04·05·06의 참조를 고쳤다.
- 04 §13의 `non-exist` 행이 "UI 미구현"으로 남아 있어 구현된 상태로 고쳤다.
- `docs/README.md`와 `README.md`의 데이터 크기·생성 파일·번들 예산 설명을 두 청크 기준으로 고쳤다.

- **미니맵**이 카메라가 바뀔 때마다 3,558칸을 다시 그린다. 03 §7.5의 설계(미리 그린 비트맵 + 12% 채움 사각형)대로 바꿔야 한다.
- **Prettier 서식**이 아닌 파일 5개(§2).
- 패널의 방향 버튼은 이웃을 `index.nuclides.find`로 한 칸씩 최대 179번 선형 탐색한다. 딸핵 찾기처럼 격자 조회로 바꿀 수 있다.
- 도움말의 앱 버전이 `0.1.0`으로 코드에 직접 적혀 있어 `package.json`과 따로 관리된다.
- 설계 문서는 최초 요구사항 메모를 `d.md`로 가리키지만 실제 파일은 `my_thought.md`다(`docs/README.md` 링크가 깨지고, 01·04·05·06 본문에도 `d.md`로 나온다). 첫 커밋부터 있던 불일치라 어느 이름으로 맞출지 정해야 한다.
- 원소 한글 이름·별칭(`src/data/elements.ts`)을 대한화학회 원소 이름표와 대조하지 않았다(06 리스크 R5).

## 10. 작업 환경과 주의점

- Windows PowerShell에서는 `npm.ps1`이 실행 정책에 막히므로 `npm.cmd`·`npx.cmd`를 쓴다(시스템 실행 정책은 바꾸지 않았다). Git Bash에서는 `npm`이 그대로 동작한다.
- Node v24.16.0 / npm 11.13.0. TypeScript 최신판 7은 린터 peer 범위 밖이라 6.0 계열을 쓴다. 실제 버전은 `package-lock.json`으로 고정한다.
- 샌드박스에서 npm 네트워크 접근이 EACCES로 막혀 도구의 승인 절차로 의존성을 설치했다. 원본 데이터는 curl로 IAEA 미러에서 받았다.
- Git Bash의 `python`은 Windows Store 스텁이라 입력을 기다리며 멈춘다. 쓰지 않는다.
- Playwright 브라우저(Chromium·Firefox·WebKit)는 설치되어 있다. Browser 스킬은 브라우저 목록이 비어 있어 쓰지 못했고, 화면 확인은 Playwright 스크린샷으로 했다.
