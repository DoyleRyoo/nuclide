- 목표 사용자 1·2순위가 없어 임의의 가중 총점이나 사용자 순위를 만들지 않았다.
- 감마 역검색·반응 단면적은 명시된 v1 범위 밖이다. 해당 분야의 업무 한계로 기록했으며 모든 사용자에게 적용되는 결함으로 세지 않았다.
- 수치 비교의 기준은 NUBASE2020/AME2020와 현재 LiveChart 응답이다. 평가본 차이가 곧 파서 오류라는 뜻은 아니다.
- 상위 318개 자동 플래그의 평가 이력 전건, 전체 이성질체 외부 전수 검증, LARAWEB 현행 UI, 실제 사용자 성공률·시간 비교는 남아 있다.
- 현재 판정은 코드·화면·공식 자료에 근거한 검토다. 전문 사용자들의 실제 사용 실험은 수행하지 않았다.

## 2차 검증 (같은 날 이어서)

남은 심층 검증을 [2차 폴더](../conformity-inspection-2026-10-02-r2/README.md)에서 이어 했다. 이 폴더의 01~03 보고서와 증거는 1차 기록으로 그대로 두었다. 2차에서 바뀐 판단은 다음과 같다.

- QA-01: 원인 확정(로컬 Pretendard 설치로 테스트 전제가 깨짐). 제품 결함이 아니다.
- 상위 318개 플래그: 모두 앱 = NUBASE2020 원문. 대부분 평가본·버전 차이이며 원인 미확정은 4건.
- NUBASE2020 원문 자체의 오기 12건이 화면에 그대로 나온다(¹⁶⁴Ho β⁻→β⁺, ¹⁸²Pt 0.962 %, ¹⁵¹Ho 88 % 등). ⁸⁴Sr 존재비 `00.56 %`는 앱 표시 결함이다.
- ²⁴²ᵐAm·²⁹⁴Og SF는 앱 표시가 ENSDF와 양립한다(LiveChart API가 부등호를 버림). ¹⁸⁰ᵐTa 존재비는 IUPAC 2013 값이다.
- **정정:** 1단계 골든 표의 “Li ±1.71 %를 자연 범위와 동일시하지 않음”은 틀렸다. 이 ±는 CIAAW 구간을 균등분포 σ로 바꾼 값이다([2차 04](../conformity-inspection-2026-10-02-r2/04-golden-abundance.md)).
- LARAWEB은 접속되며 시나리오 F를 한 번의 검색으로 끝낼 수 있다.
