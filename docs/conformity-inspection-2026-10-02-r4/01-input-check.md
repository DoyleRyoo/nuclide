# 4차 1-0 — 공통 B 입력 점검

검증일: 2026-10-02. 개발자가 [conformity_inspection.md](../conformity_inspection.md)의 공통 B를 채웠다(작업 트리 변경, 아직 커밋 전). 검증 문서의 1-0 규칙대로 **입력이 실제 앱과 맞는지**를 1~3차 증거로 대조했다. 입력이 앱과 다르면 앱을 기준으로 판정하고, 차이는 개발자가 정할 사항으로 남긴다.

## 결론

입력 17칸 중 **5칸이 실제 앱과 다르다.** 출처(반감기·붕괴·존재비), 딸핵종 결정 방식, 방사선 방출·단면적 포함 여부, 이성질체 기준, 안정 기준이다. 이 중 출처·방출·단면적은 검증 판정과 인용 신뢰에 직접 영향이 있어 공개 전에 입력이나 앱 중 하나를 고쳐야 한다. 비어 있는 5칸은 확인 불가로 두거나 1~3차에서 확인한 사실로 채웠다.

## 딸핵종 결정 방식에 대한 제안 (적용하지 않음)

입력의 의도는 “확실하지 않은 것을 계산으로 지어내지 말자”로 읽힌다 [추정]. 이 의도와 원문의 한계를 함께 맞추는 방법:

- **딸 핵종(Z, A)은 계산을 유지한다.** β⁻는 Z+1, α는 Z−2·A−4처럼 붕괴 모드만으로 정해지는 물리 규칙이라 ‘추측’이 아니다. 데이터에서만 읽으면 거의 모든 링크가 사라진다.
- **딸 상태(바닥/이성질체)는 데이터에서만 읽는다.** 원문 주석이 있으면 그 상태로 연결하고, 없으면 “딸 상태 미상”으로 둔다. 1차 SCI-04(¹³⁷Cs → ¹³⁷ᵐBa)가 이 지점의 문제다.
- SF·다중 클러스터처럼 딸이 하나로 정해지지 않는 모드는 지금처럼 공란이다(1차 확인).

## 개발자가 정할 사항

1. 2순위 “관련 종사자”에 포함할 공통 A 태그.
2. 출처: 입력(ENSDF·CIAAW)을 앱(NUBASE2020)에 맞춰 고칠지, 앱 출처를 바꿀지.
3. 방출·단면적: “y”가 계획이면 출처(예: 방출 = ENSDF/DDEP, 단면적 = ENDF/B-VIII.0·JENDL)와 범위를 정한다. 아니면 입력을 “n”으로 고친다.
4. 범위 “둘 다”가 요구사항 문서의 v1 제외 목록을 대체하는지.
